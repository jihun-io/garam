# Garam 디자인 원칙: 계기(Instrument)

Garam은 **정밀한 도구**처럼 보여야 한다. 사용자가 보는 것은 앱이 아니라 자기 코드와 기록이다. 화면의 장식은 물러나고, 의미가 있는 것만 앞으로 나온다.

이 문서는 "왜 이 색, 왜 이 모양인가"에 답한다. 구체적인 규칙(커서, 단축키, 접근성 등)은 `docs/UI.md`, 값은 `src/styles/tokens.css`에 있다. 화면을 만들거나 고칠 때 이 문서의 원칙과 어긋나면 원칙을 먼저 고치고 나서 코드를 바꾼다.

## 1. 다섯 가지 원칙

### 1.1 색은 의미다

- 화면의 바탕(창, 사이드바, 본문, 선)은 **채도가 거의 없는 흑연색 회색**이다. 아주 약한 푸른 기(hue 265, chroma ≤ 0.006)만 둔다. 녹색·분홍 같은 파스텔 회색은 쓰지 않는다.
- 색이 있는 것은 셋뿐이다.
  1. **강조색**: 사용자가 고른 것(선택된 행), 지금 키보드가 있는 곳(포커스), 이 화면의 주된 행동(커밋 버튼). 그 외에는 쓰지 않는다.
  2. **상태색**: 추가(초록), 수정(호박), 삭제·충돌·위험(빨강), 이름 변경(파랑). 파일과 줄의 상태에만 쓴다.
  3. **diff 배경**: 추가·삭제 줄. 상태색을 아주 옅게 깐 것이다. 줄 안에서 바뀐 낱말은 줄 여백(줄 번호)과 같은 한 단계 진한 색을 쓴다.
- **구문 색**은 코드 글자에만 쓰는 예외다. 여섯 가지(키워드, 문자열, 상수, 함수, 타입, 주석)로 묶고, 상태색과 헷갈리지 않게 초록·빨강 계열은 피한다(`--color-syntax-*`). 모든 diff 배경 위에서 4.5:1을 넘긴다. 커밋에서 뺀 줄도 구문 색을 유지한다(처음에는 모든 줄이 빠져 있으므로). 포함 여부는 배경 농도와 줄 여백으로 구별한다.
- 커밋 그래프도 한 가지 색(흐린 잉크)으로 그린다. 레인마다 색을 바꾸면 색이 아무 뜻 없이 화면을 채운다. HEAD(고리), 커밋하지 않은 변경 사항(점선 원), 스태시(빈 사각형)는 모양과 점선으로 구별한다.
- 같은 색이 두 가지 뜻을 갖지 않는다. 예를 들어 "진행 중인 병합" 안내는 수정 색(호박)을 빌리지 않고 경고 아이콘과 문장으로 알린다.
- 색 토큰은 불투명하다. 투명도(`rgba`)는 배경 막(scrim)과 그림자에만 쓴다. 투명한 토큰은 무엇 위에 있느냐에 따라 다른 색이 된다.

### 1.2 면은 두 겹, 선은 한 굵기

- 면은 두 단계다: **창(chrome)**(툴바, 사이드바, 탭)과 **내용(content)**(diff, 커밋 상세, 입력 필드). 팝오버·메뉴·대화상자는 그 위에 뜨는 **떠 있는 면(raised)**이다. 이 셋 말고 새 면을 만들지 않는다.
- 상자 안에 상자를 넣지 않는다. 영역은 면의 차이와 1px 선 하나로 나눈다. 테두리와 배경을 둘 다 바꾸는 카드는 쓰지 않는다.
- 선은 1px 하나다(`--color-line`). 컨트롤 테두리만 조금 진하다(`--color-line-strong`). 왼쪽에 색 막대를 세운 안내 상자(side-stripe)는 쓰지 않는다.

### 1.3 OS의 문법을 따른다

- 글꼴은 **시스템 글꼴**이다(macOS SF Pro, Windows Segoe UI Variable, 한글은 Apple SD Gothic Neo / 맑은 고딕). 데스크톱 도구가 고유한 글꼴을 쓰면 웹 페이지처럼 보인다. 고정폭 글꼴은 코드, 해시, diff에만 쓴다.
- 메뉴 막대·오른쪽 클릭 메뉴·버튼에서 여는 명령 메뉴는 실제 OS 메뉴를 쓴다. 이 메뉴의 색·면·모서리·위계·움직임은 OS에 맡기며, 아래 앱 자체 컨트롤의 토큰 규칙에서는 제외한다.
- 선택은 포커스가 바뀌어도 유지한다. 활성 창에서 포커스를 가진 목록의 선택만 강조색을 쓰고, 다른 목록이나 비활성 창의 선택은 중립 회색으로 표시한다. 포커스 링은 키보드 탐색에서만 보인다.
- 컨트롤은 OS 컨트롤처럼 생긴다: 세그먼트 컨트롤(탭), 테두리 있는 푸시 버튼, 강조색으로 채운 기본 버튼, 안쪽으로 들여 둥글린 목록 선택(Finder·Xcode 사이드바처럼).
- 모서리는 크기를 따른다: 작은 것(체크박스, 배지, 키 표시) 4px, 컨트롤(버튼, 입력, 목록 행) 6px, 떠 있는 면(메뉴, 팝오버, 대화상자, 알림) 10px. 알약 모양(완전한 둥근 끝)은 쓰지 않는다.

### 1.4 위계는 무게와 간격으로

- 글자 크기는 네 단계뿐이다(11 · 13 · 18 · 28px). 위계는 크기보다 굵기(400 / 550 / 650)와 색(잉크 / 흐린 잉크)으로 만든다.
- 간격은 4px 단위(4 · 8 · 12 · 16 · 24 · 32 · 48)만 쓴다. 같은 종류의 영역은 같은 안쪽 여백을 갖는다(목록 머리 36px, 행 28px, 툴바 52px).
- 굵게(550 이상)는 이름과 제목에만 쓴다: 파일 이름, 브랜치 이름, 커밋 요약, 영역 제목.

### 1.5 움직임은 상태가 바뀌었다는 신호일 때만

- 나타나는 면(팝오버, 메뉴, 대화상자, 알림)만 120~160ms 동안 페이드와 아주 작은 이동으로 들어온다. 목록, 탭 전환, 선택 변경은 즉시 바뀐다.
- 성공은 조용히 알린다. 축하하는 연출은 없다. 되돌릴 수 없는 작업만 확인을 묻는다.
- 움직임 줄이기 설정이면 모두 끈다.

## 2. 토큰

| 역할        | 토큰                                                                             | 쓰는 곳                                            |
| ----------- | -------------------------------------------------------------------------------- | -------------------------------------------------- |
| 창 면       | `--color-bg`                                                                     | 툴바, 사이드바, 탭 줄                              |
| 내용 면     | `--color-surface`                                                                | diff, 커밋 상세, 입력 필드, 버튼                   |
| 떠 있는 면  | `--color-raised`                                                                 | 메뉴, 팝오버, 대화상자, 알림, 툴팁 제외            |
| 누름·지나감 | `--color-hover`                                                                  | 행·버튼에 마우스가 있을 때, 세그먼트 컨트롤의 바탕 |
| 선          | `--color-line` / `--color-line-strong`                                           | 영역 경계 / 입력·버튼 테두리                       |
| 글자        | `--color-ink` / `--color-ink-muted` / `--color-ink-faint`                        | 본문 / 보조(4.5:1 이상) / 테두리·비활성·장식 전용  |
| 강조        | `--color-river`(설정의 강조색) · `--color-selected` · `--color-focus`            | 주된 행동 / 선택된 행 / 포커스                     |
| 선택 유지   | `--color-selected-inactive`                                                      | 포커스가 없는 목록·비활성 창의 선택                |
| 상태        | `--color-added-ink` · `--color-modified-ink` · `--color-danger` · `--color-link` | 추가 / 수정 / 삭제·충돌·위험 / 이름 변경·링크      |

다크 테마는 같은 색상(hue)을 유지하고 명도만 옮긴다. 떠 있는 면은 더 밝아진다(그림자가 잘 보이지 않으므로).

## 3. 하지 않는 것

- 파스텔 회색, 회색에 섞은 녹색·분홍 기운
- 알약 모양 버튼·배지, 그라데이션, 유리 효과, 빛나는 그림자
- 왼쪽 색 막대가 있는 안내 상자, 카드 안의 카드
- 색만으로 구별하는 상태(아이콘 모양이 함께 다르다)
- 강조색으로 넓은 면 채우기(기본 버튼과 선택된 행 정도만)
- 화면마다 다른 모서리, 그림자, 여백
